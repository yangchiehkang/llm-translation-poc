## B-001 源码交付甲方前必须轮换 API_TOKENS 并重发文档

**状态**：待办，触发式（2026-08-01 记录，当前决定不动）

**触发条件**：**源码交付甲方之前**（或任何形式的仓库外发、代码审计、第三方接触版本库）。

**事由**：《标准法规翻译接口·调用说明 v2.2》的 docx **内联了完整的 guochuang token**
（`docs/deliverables/标准法规翻译接口_调用说明_v2.2.docx`，文内出现 3 次），
且该文件**已被 git 跟踪**——即这枚生产 token 已进入版本库历史。

`git grep` 扫不出来：docx 是 zip 压缩包，纯文本扫描进不去。因此常规的
"仓库里搜一遍密钥"检查**会漏掉它**，这也是它一直没被发现的原因。

**必须做的动作**（触发时）：

1. 轮换 `API_TOKENS`：在 125 的 `.env` 里换发新的 `guochuang_` 与 `selftest_` 两枚；
2. 用新 token 重新生成《调用说明》并**重发国创**
   （`GUOCHUANG_TOKEN=<新值> python3 scripts/reporting/make_call_guide_docx.py ...`）；
3. 视交付范围决定是否清理 git 历史（`git filter-repo` 或重建仓库）——
   仅删除当前文件**无效**，历史里仍在。

**不做的后果**：拿到源码的人即可从 git 历史中取出生产 token，直接调用生产翻译接口。

**当前为何不做**：尚未向甲方交付源码，token 仅在我方与国创之间流转；
现在轮换需同步协调国创改配置，收益低于扰动。**一旦进入交付流程即必须执行。**

**相关**：v3.0 起生成器不再硬编码 token（由环境变量 `GUOCHUANG_TOKEN` 注入，
产物落 `outputs/`，已 gitignore），**新增的文档不会再扩大暴露面**。
