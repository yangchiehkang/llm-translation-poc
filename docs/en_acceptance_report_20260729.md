# 三、Y3 候选重排序（本次唯一采纳的改进）

**方法**：每条生成 4 个候选（候选 0 = 原 temp=0 贪心输出；候选 1–3 为
temp=0.7 / top_p=0.9 采样，**seed = 20260728 + 候选序号，固定并逐条落盘**）。
两级排序：**先过 TCR 硬术语检查 → 在通过者中按 XCOMET-QE 取最高 → 无通过者回落候选 0**。
该设计保证 **TCR 只增不减、DA 不低于基线**。

| | 值 |
|---|---|
| 候选总数 | 2756（689 × 4） |
| 过 TCR | 2583（93.7%） |
| 每条通过候选数 | 均值 3.75 |
| 无候选过 TCR → 回落候选 0 | 27 条 |
| **候选 0（贪心）获胜率** | **36.9%** |
| 候选 1 / 2 / 3 获胜 | 23.9% / 19.4% / 19.7% |

候选 0 只赢 36.9%，说明**重排序空间是实的**，不是聊胜于无。

## 诚实性检验（决定这个方法算不算数）—— **通过**

| severity | 臂 A | Y3 | 变化 |
|---|---:|---:|---:|
| critical | 7 | 7 | ±0 |
| **major** | **598** | **429** | **−169（−28.3%）** |
| minor | 928 | 896 | −32（−3.4%） |

**major 显著下降 28.3% → 译文真的变好了，不是在优化指标本身。**

交叉验证：**QE 涨 +0.0331，DA 涨 +0.0218**，DA 增益是 QE 增益的 66%。
若是过拟合到重排序器，应当 QE 大涨而 DA 几乎不动——实际不是。

## TCR

实测（全集 689 上重算，非复制臂 A 数字）：**术语级 97.56%（1119/1147）、样本级 95.05%（518/545）**，
均高于臂 A 的 96.51%/92.84%。两级排序的第一级即为 TCR 硬检查，故重排序**不会降低 TCR**——
这次是设计保证与实测数一致，而非早先版本里"设计上不会变"就直接照抄臂 A 数字。

# 七、C1 少样本对照（今晚补跑，判据不变）

**方法**：零样本臂（臂 A）之外，加两种少样本来源 × 两档 shot 数，共四臂，
均用臂 A 的 prompt 模板注入示例、temp=0 贪心生成：

| 臂 | 示例来源 | k |
|---|---|---|
| random_k2 / random_k5 | 评测集内**其它行**的参考译文（`c1_gen.py` 的 pool 即评测集本身） | 2 / 5 |
| curated_k2 / curated_k5 | **R016 训练对**里人工挑选的 5 条（定义/程序/验收判据/表格数值各一类） | 2 / 5 |

⚠️ **两种来源不对等**：random 臂对评测集存在 **leave-one-out 式泄漏**
（示例本身就是评测集的参考译文），其增益系统性上偏；curated 臂取自 R016 训练对，
**对评测集三个维度零泄漏**——已核验 sample_id 交集、源文全文交集、参考译文交集均为 0，
且评测集 689 条全部来自 R100/R17 文档，curated 示例全部来自 R016，无文档重叠。

## 结论：C1（本次实现）不是正收益

**唯一零泄漏的臂（curated）在段级和句级全量均为负**（−0.0063 / −0.0040 于 k=2，
−0.0018 / −0.0014 于 k=5）。random 臂段级/句级全量为小幅正值
（+0.0005~+0.0027），但**这个正值本身不可信**——它来自对评测集的 leave-one-out
泄漏，增益方向和大小都可能是"背答案"的产物，不能当作少样本本身的效应。

**5 条精选示例撑不起 689 条的多样性**是最直接的原因：k=5 时同一组示例反复注入，
在"定义/程序/验收判据/表格数值"四类之外的源文上大概率文不对题，
这正好解释了 curated 臂比 random 臂**更差**——random 好歹是同分布内容，curated
示例类型固定但源文类型多样，错配概率更高。

**成本**：curated_k5 生成耗时 40.0 分钟（四臂中最长，其余约 24–25 分钟）；
逐字比对显示少样本确实改变了输出（与臂 A 逐字相同仅 14.8%–23.8%，非空转）。

判据不变：TCR < 95% 一律否决——四臂全部通过，但门禁通过不等于有收益，
**方法本身在当前示例规模下未证明正收益**。

**与 Y3 的叠加关系（机制仍然成立，但本次不满足触发条件）**：C1 改的是生成
（往 prompt 里注入示例），Y3 改的是选择（同一 prompt 生成 4 候选后挑一个），
两者作用在流水线的不同环节，理论上可以叠加——**若 C1 证明正收益，"少样本 +
重排序"就该是下一阶段的默认配置**。但今晚的结果是唯一零泄漏的 curated 臂两项
全量均为负，条件不成立，因此**眼下不推荐叠加**；C1 若要翻案，需要先解决
"5 条精选示例覆盖不了 689 条多样性"这个根因（更大的精选示例库，或按源文类型
做检索式挑选而非固定注入），而不是简单调大 k。
