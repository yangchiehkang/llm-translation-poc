## 3. Field Structure

The V0.2 termbase uses a stable 10-column schema:

```text
term_id,source_lang,target_lang,source_term,target_term,domain,priority,alias,note,status
```

Field definitions:

| Field | Description |
|---|---|
| `term_id` | Stable term ID |
| `source_lang` | Source language code, such as `en`, `de`, `fr`, `ar`, `ms` |
| `target_lang` | Target language code, currently mostly `zh` |
| `source_term` | Source-language term |
| `target_term` | Approved Chinese translation |
| `domain` | Domain category, such as `vehicle_approval`, `vehicle_safety`, `testing` |
| `priority` | Term priority: `high`, `medium`, or `low` |
| `alias` | Synonyms, abbreviations, or term variants |
| `note` | Context, ambiguity, usage notes, or translation constraints |
| `status` | Term status: `active`, `review`, or `deprecated` |

This schema is intended to remain stable for downstream scripts.

## 6. Priority Distribution

The `priority` field has been normalized to three allowed values:

```text
high
medium
low
```

Current distribution:

| Priority | Count |
|---|---:|
| `high` | 3175 |
| `medium` | 1268 |
| `low` | 46 |

Priority rules:

### 6.1 High

Terms are marked as `high` when they meet one or more of the following conditions:

- core automotive regulation concepts;
- stable and unambiguous Chinese translation;
- mistranslation may affect regulatory understanding;
- suitable for stricter use in Prompt V2;
- suitable for terminology consistency calculation.

Examples:

| Source Term | Target Term |
|---|---|
| `type approval` | 型式批准 |
| `technical regulation` | 技术法规 |
| `conformity assessment` | 合格评定 |
| `braking system` | 制动系统 |
| `rear-view mirror` | 后视镜 |
| `safety requirement` | 安全要求 |

### 6.2 Medium

Terms are marked as `medium` when they are common and useful but may vary slightly by context.

Examples:

| Source Term | Target Term |
|---|---|
| `manufacturer` | 制造商 |
| `inspection` | 检查 |
| `verification` | 验证 |
| `performance` | 性能 |
| `compliance` | 合规 / 符合性 |

### 6.3 Low

Terms are marked as `low` when they are broad, context-dependent, or unsuitable for strict replacement.

Examples:

| Source Term | Target Term |
|---|---|
| `system` | 系统 |
| `part` | 部件 / 零件 |
| `device` | 装置 |
| `test` | 试验 / 测试 |
| `shall` | 应 |
| `may` | 可 |

## 8. Broad-Term Cleaning Rules

The V0.2 plan requires special attention to broad terms that may cause false matches.

Terms that require caution include:

```text
system
part
device
test
standard
shall
may
requirement
```

General treatment rules:

| Case | Treatment |
|---|---|
| Standalone and context unclear | Downgrade to `low` or mark as `review` |
| Part of a fixed phrase | Keep as `medium` or `high` |
| High false-match risk | Add usage note in `note` |
| Clearly low-value | Mark as `deprecated` or remove |
| Core regulatory expression | Keep, but avoid over-enforcement |

Examples of fixed phrases that should be retained:

| Source Term | Target Term | Priority |
|---|---|---|
| `braking system` | 制动系统 | `high` |
| `lighting system` | 照明系统 | `high` / `medium` |
| `steering system` | 转向系统 | `high` |
| `test procedure` | 试验程序 | `high` |
| `safety requirement` | 安全要求 | `high` |

The validation script identified:

```text
possible_broad_terms: 4
```

These items should be reviewed manually if further cleanup is needed.

## 11. Downstream Usage Notes

```text
source_lang
target_lang
source_term
target_term
priority
status
```

For Prompt V2 terminology injection, the recommended fields are:

```text
source_term
target_term
priority
note
```

Recommended filtering strategy for downstream scripts:

```text
status == active
```

For stricter terminology control, downstream scripts may prioritize:

```text
priority == high
```

Recommended Prompt V2 usage logic:

| Priority | Suggested Usage |
|---|---|
| `high` | Strongly enforce when context matches |
| `medium` | Use as reference, avoid mechanical replacement |
| `low` | Use cautiously; mostly for review or fallback reference |
